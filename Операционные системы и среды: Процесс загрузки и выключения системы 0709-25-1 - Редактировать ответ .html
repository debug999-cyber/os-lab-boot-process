Лабораторная работа: Процесс загрузки и выключения системы

Данная лабораторная работа направлена на приобретение практических навыков работы с загрузчиком GRUB и системой инициализации systemd в операционной системе Astra Linux. Студенты освоят методы настройки параметров загрузки ядра, управления паролями пользователей и GRUB, а также создания и конфигурирования системных служб.

В ходе выполнения работы рассматриваются ключевые аспекты процесса загрузки Linux, включая передачу параметров ядру, защиту загрузчика, настройку таймаутов и создание собственных systemd-юнитов для автоматизации системных задач. Работа закрепляет понимание архитектуры загрузки Linux и принципов управления системными службами.

📋 Теоретическая справка

Процесс загрузки Linux

Процесс загрузки Linux состоит из нескольких этапов:

  1. BIOS/UEFI - инициализация оборудования и поиск загрузчика
  2. GRUB - загрузчик, позволяющий выбрать ядро и передать параметры
  3. Ядро Linux - инициализация системы, монтирование корневой файловой системы
  4. systemd - инициализация пользовательского пространства и служб

GRUB (Grand Unified Bootloader)

GRUB - это многостадийный загрузчик, который позволяет:

  • Выбирать операционную систему для загрузки
  • Передавать параметры ядру при загрузке
  • Работать с различными файловыми системами
  • Защищать доступ к настройкам загрузки паролем

Systemd и юниты

Systemd - это система инициализации и менеджер служб в современных дистрибутивах Linux. Юниты (units) - это конфигурационные файлы, описывающие:

  • Службы (services)
  • Точки монтирования (mounts)
  • Сокеты (sockets)
  • И другие системные ресурсы

🚀 Настройка параметров, смена паролей и проверка корректности его смены

1. Настройка параметров загрузки через GRUB

Теоретическая часть: Параметры ядра передаются в командной строке и влияют на поведение системы при загрузке. Ключевые параметры включают режим монтирования корневой файловой системы и указание программы, запускаемой с PID=1.

Используя редактор пунктов меню GRUB, настройте параметры, передаваемые ядру при загрузке Astra Linux:

  • Примонтируйте в корневой каталог устройство в режиме Чтение/Запись
  • Укажите полный путь к программе /bin/bash, выполняемой с PID=1

Процедура: Во время загрузки системы при появлении окна меню GRUB нажмите «e», на запрос ввода имени пользователя введите имя администратора системы, при запросе пароля введите пароль GRUB.

Теоретическая часть: Утилита passwd используется для изменения паролей пользователей. Она обновляет хэш пароля в файле /etc/shadow, обеспечивая безопасное хранение учетных данных.

Смените пароль у пользователя системы, используя утилиту passwd (см. рис. 2):

3. Проверка смены пароля

Проверьте корректность смены пароля: перезагрузите машину и войдите с новым паролем в графическом интерфейсе (для выхода из консоли bash нажмите Ctrl+Alt+Del).

4. Смена пароля GRUB

Теоретическая часть: Защита GRUB паролем предотвращает несанкционированный доступ к параметрам загрузки, что особенно важно для систем с повышенными требованиями безопасности.

Для смены пароля GRUB воспользуйтесь командой grub-set-password.

Пересоберите GRUB с помощью update-grub. Дополнительные сведения можно получить в info grub (см. рис. 3).

5. Проверка смены пароля GRUB

Проверьте корректность смены пароля: перезагрузите машину и войдите с новым паролем в редактор команд GRUB.

6. Настройка GRUB-таймаута

Теоретическая часть: Таймаут GRUB определяет время ожидания перед автоматической загрузкой системы по умолчанию. Настройка таймаута важна для автоматизации процесса загрузки и повышения безопасности.

Поменяйте GRUB-таймаут на 10 сек с обратным отсчетом времени и без показа меню.

Задание выполните с помощью внесения изменений в файл /etc/default/grub, параметры описаны в info grub → * Configuration:: (см. рис. 4).

🛠️ Создание unit

1. Создание unit типа service

Теоретическая часть: Systemd юниты позволяют автоматизировать запуск и управление системными службами. Юнит типа service описывает как управлять конкретной службой, включая команды запуска, остановки и условия зависимости.

Создайте unit (типа service) для включения маршрутизации в ядре (переменная net.ipv4.ip_forward).

Порядок выполнения:

1. Создание юнита:

Создайте юнит с именем ip_forward.service (см. рис. 7):

sudo systemctl --force --full edit ip_forward.service

Рисунок 7. Создание юнита службы systemd

2. Настройка секции [Unit]:

В секции [Unit] параметру Description присвойте краткое описание:

Description=Turn on/off internal routing

3. Настройка секции [Service]:

Теоретическая часть: Секция [Service] определяет поведение службы. Тип oneshot используется для служб, которые выполняют одну операцию и завершаются, а параметр RemainAfterExit указывает, что служба считается активной даже после завершения основного процесса.

  • Тип службы: Type=oneshot
  • Параметр для сохранения состояния после выполнения: RemainAfterExit=yes
  • Команда запуска: ExecStart=/usr/sbin/sysctl net.ipv4.ip_forward=1
  • Команда остановки: ExecStop=/usr/sbin/sysctl net.ipv4.ip_forward=0

4. Настройка секции [Install]:

Задайте многопользовательский режим без графического интерфейса:

WantedBy=multi-user.target

5. Сохранение юнита:

Сохраните юнит с параметрами по умолчанию (см. рис. 8):

Рисунок 8. Сохранение конфигурации юнита

6. Перезагрузка конфигурации:

Перечитайте конфигурационный файл службы:

sudo systemctl daemon-reload

7. Запуск и проверка службы:

Запустите созданную службу и проверьте корректность работы (см. рис. 9):

Рисунок 9. Проверка состояния созданной службы

8. Добавление в автозагрузку:

Добавьте службу в автозагрузку:

sudo systemctl enable ip_forward.service

2. Проверка работы службы

Проверьте корректность работы службы ip_forward.service после перезагрузки ОС.
